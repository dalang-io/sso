The open-source Keycloak alternative.

A self-hosted OAuth 2.0 / OpenID Connect provider in Rust — your own “Sign in with…”, on your domain. Fine-grained authorization (roles, groups, resource-based RPT), TOTP two-factor, multi-tenant RBAC, post-quantum tokens, SDKs for six languages, airgap-ready. One ~8 MB binary, not a JVM.

OAuth 2.0 & OIDC

Authorization Code + PKCE, refresh rotation, client credentials, discovery, JWKS, UserInfo. Standards-compliant.

Multi-tenant RBAC

Isolated tenants with super / manager / developer roles. Managers own their clients; developers only rotate secrets.

Post-quantum ready

Optional ML-DSA (FIPS 204) token signing. Argon2 + SHA-256 hashing. Hybrid ML-KEM at the TLS edge.

SDKs for 6 languages

JavaScript/TypeScript, Rust, Go, Python, Java, PHP — PKCE, token exchange, refresh, UserInfo, all consistent.

Any database

SQLite by default (zero setup). PostgreSQL, MySQL & MariaDB by config. No recompile to switch.

Airgap & tiny

No CDN, no external fonts, one static binary with an embedded dashboard. Runs where the internet doesn’t reach.

Fine-grained, Keycloak-style — built in

Not just “sign in”. Control exactly what each app and each user can do, with tokens that carry the answer.

Roles, groups & attributes

Every user carries roles, groups, and custom attributes, echoed straight into id/access tokens. Enforce on the client side without a DB round-trip.

Per-client claim mapping

Each app opts into which claims it receives — roles, groups, or attributes can be included or stripped per client to keep tokens lean and scoped.

Resource-based authorization

Define resources and role/group policies per client. The access token becomes a requesting-party token (authorization claim) listing what the user can do.

Token introspection

RFC 7662 /oauth/introspect — a resource server can centrally authenticate and read any access or refresh token, including its RPT permissions.

TOTP two-factor

Standard TOTP (RFC 6238) via any authenticator app. Mandate it per client, and let users enroll their own 2FA on a self-service page.

End-user self-service

Each user gets an /account page: change their password, and enroll or disable their own 2FA — no admin needed.

Dalang SSO vs. Keycloak

Both are open-source identity providers. Dalang packs the commercial-grade features into a small, fast, operable core.

Running in 60 seconds

# download the latest release binary (or `cargo build --release`) curl -L https://github.com/dalang-io/sso/releases/latest/download/sso-linux-x86_64 -o sso chmod +x sso && ./sso # open http://localhost:8080 → create your super admin → add an OAuth client

Then drop an SDK into your app and run the Authorization Code + PKCE flow against your instance. Full walkthrough in the docs.
